# MSL HFDEM Downloader Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add safe, provenance-rich MSL archive acquisition and clipped HFDEM generation without changing OpenTopography.
**Architecture:** Shared stdlib acquisition/metadata contract, optional rasterio headless processor and native ArcPy adapter. Thin CLI and toolbox front ends.
**Tech Stack:** Python >=3.10, urllib, zipfile, optional rasterio/pyproj/pyshp, ArcGIS Pro >=3.5.
**Spec:** docs/superpowers/specs/2026-11-10-msl-hfdem-design.md

## Global Constraints
- Core/adapters import without arcpy or arcgis.
- Archive-first; multiple projects require explicit selection.
- Unknown resolution/accuracy/confidence stays unknown; preserve all evidence sources.
- Preserve native resolution by default; no implicit vertical transformation.
- Default total download gate 1 GiB; unknown sizes require explicit authorization.
- All writes in claimed feature worktree. No external publication.

## Review Focus
- Polygon holes/selection survive discovery and clipping; source bounding boxes are not coverage.
- Malformed REST pages, HTTP 200 HTML, unsafe ZIP paths and interrupted downloads cannot produce success.
- Cache and archive attribution bind provenance to actual bytes, never original-delivery metadata guessed onto distributed artifacts.
- Output/cache collisions and processing failures preserve existing data.
- Missing optional dependencies, ArcPy licensing and native CRS/NoData semantics fail actionably.
