# Report Template System — Design

**Date:** 2026-07-10
**Issue:** #163 — "No PDF/Word report-template system — recurring gap across two report tools"
**Status:** Approved (brainstorming), pending implementation plan

## Problem

Two envmon report tools emit **plain Markdown** with no styling, no print/PDF path, and
no photo support:

- `well_inspection_report.py` (CLI `well-inspection-report`) — narrative + inspection
  history tables, Markdown only. Photo attachments were logged as "an undesigned blocker".
- `generate_event_report.py` (ADR-0028) — data-dense monitoring-event report, Markdown only.

A third tool, `well_inspection_photo_report.py` (ADR-0046, Tool 7.4), *does* embed field
photos — but as an **XLSX workbook**, with no narrative and nothing styled. So no tool
produces a sleek report combining **narrative + history + photos**.

#163 asks for a **deliberate, documented** report-template decision (templating approach,
photo handling) rather than per-tool improvisation.

## Decision (scope, confirmed with user)

- **"Multi-format" = multi report-TYPE**, not multi output-format. One template system
  serves well-inspection and monitoring-event reports (extensible to boring-log), each with
  a **single output format: self-contained HTML**.
- **Output = self-contained HTML**, print-optimized (`@media print`) so PDF is one browser
  Ctrl-P away. **No `weasyprint`, no `python-docx`.** DOCX and a PDF-rendering library are
  explicitly **deferred** (documented, not attempted).
- **Sleek design lives in a DesignSync (claude.ai/design) project** = the canonical *visual
  spec*. A Python render layer inlines the **same CSS**, so design and code cannot drift.
- **Additive, coexisting**: Markdown stays the default output; HTML is a new `--format html`
  path. The existing XLSX photo tool is left untouched.

## Rejected alternatives

- **Jinja2 behind a `report=[jinja2]` extra** — cleaner templates, but a new dependency +
  optional-extra gating and a second failure mode, overkill for the table/card/photo-grid
  shapes here. Stdlib string templating matches these tools' existing pure-stdlib ethos.
- **HTML + PDF + DOCX now** — DOCX has no clean high-fidelity path; a separate hard problem.
- **Design-only (no Python wiring)** — does not resolve #163.
- **HTML supersedes the XLSX photo tool** — bigger call touching a shipped tool + ADR-0046;
  user chose coexist.

## Architecture

### The single-source-of-truth CSS

One canonical stylesheet, `autogis/core/common/report_assets/report.css`, is consumed by
**two** things:

1. **DesignSync component library** → pushed to a new claude.ai/design project
   ("AutoGIS Report Templates"). The *visual spec* — reviewable, iterable.
2. **Python render layer** (`report_html.py`) → inlines that same file into every
   self-contained HTML report.

Because both read the same CSS, the design in claude.ai/design and the reports the tools
emit stay in lockstep.

### § A — DesignSync component library

A local bundle (built in the worktree, pushed via the `DesignSync` tool) of preview HTMLs,
each carrying a first-line `<!-- @dsCard group="…" -->` marker. Groups:

- **Foundations** — neutral palette + one accent, system-font stack, type scale, spacing
  tokens. Report canvas is **always light** (documents print on white); DesignSync
  *previews* stay theme-aware per pane norms.
- **Report shell** — cover/title block, metadata strip, footer ("Generated by AutoGIS…").
- **KPI row** — tone-colored stat tiles (e.g. *Total wells / Never inspected / Needs
  attention*; *Results / Exceedances / Gaps / RPD errors*).
- **Data table** — refined bordered/zebra table with per-cell status tone.
- **Status badge** — `ok` / `warn` / `bad` / `info` / `neutral`.
- **Inspection card** — per-well: latest condition + history.
- **Photo grid** — responsive captioned image grid (closes the #163 photo blocker for the
  narrative report).

Design language: generous whitespace, subtle 1px borders, restrained accent, print CSS.

### § B — Python render layer: `autogis/core/common/report_html.py`

Arcpy-free, **stdlib-only** core, escape-safe (`html.escape` on every value). Small pure
builders mirroring the components:

```python
render_document(*, title, subtitle, meta, sections, generated) -> str
    # full self-contained HTML doc; inlines report.css from report_assets/
kpi_row(items: list[tuple[str, str, str]]) -> str          # (label, value, tone)
table(headers, rows, *, tone_of=None) -> str               # tone_of(row_index, col) -> tone|None
badge(text, tone) -> str
card(title, body_html) -> str
section(heading, body_html) -> str
photo_grid(images: list[tuple[str, str]]) -> str           # (data_uri_or_src, caption)
```

- `tone` ∈ `{ok, warn, bad, info, neutral}`.
- CSS is read once from `report_assets/report.css` and inlined into `<style>` so the output
  is a single portable file (email/archive/print).
- **No new runtime dependency** for the core. The **photo-embedding path** reuses the
  **existing `autogis[report]` extra** (Pillow, lazy-imported) — no *new* dep; no-photo
  reports need nothing.

### § C — Integration (both tools, additive)

**`well_inspection_report.py`**
- Add `generate_well_report_html(...)`, `generate_site_summary_html(...)`.
- `build_well_inspection_reports` gains `emit_html: bool` and optional photo inputs
  (`manifest_path`, `harvest_dir`). Photos **reuse the existing pipeline**:
  `match_photos_to_wells(manifest_rows, harvest_dir)` groups harvested photos by well ID;
  `_prepared_image_bytes(path, box)` returns EXIF-corrected RGB JPEG thumbnails →
  base64 `data:` URI → `photo_grid`. Same **pilot assumption** (well_id = first path
  component of `saved_path`) and same QA tripwires (`wells_without_photos`,
  `photos_without_record`) as the XLSX tool, inherited by reuse.
- **Markdown stays the default**; HTML is additive.

**`generate_event_report.py`**
- Add `generate_event_report_html(...)`. Reuse the existing `DisplayColorClass`
  ("EXCEED"/"OK") → badge/tone mapping.

**CLI (`autogis/adapters/cli.py`)**
- Add `--format {md,html}` (default `md`) to `generate-event-report` (line ~1261) and
  `well-inspection-report` (line ~1306). For well-inspection HTML, add optional
  `--manifest` / `--harvest-dir` to enable the photo grid (omitted → photoless HTML,
  pure-stdlib). No existing behavior changes.

### § D — ADR

New **ADR-0082** (verify vs `origin/main` + open PRs at commit time): *"Report template
system — self-contained HTML + inline CSS + stdlib string templating; DesignSync project as
the canonical visual spec; print-CSS as the PDF path; DOCX and PDF-rendering libraries
explicitly deferred; photo embedding reuses the existing `autogis[report]` extra."* Closes
#163.

### § E — Testing (stdlib-only, no network/arcpy)

- **Render layer**: XSS/escaping (a `<script>` cell renders inert), `table`/`kpi_row`/
  `badge`/`photo_grid` structure, **self-contained** assertion (zero external `http(s)://`
  or external `href`/`src` refs), deterministic output for fixed input.
- **Tool HTML paths**: well-inspection HTML contains each well ID, the history table, and
  `<img data:...>` when a manifest+harvest_dir with a matching photo is supplied; event HTML
  contains the exec-summary KPI row and exceedance badges. No-photo path imports/runs with
  neither Pillow nor arcpy installed.

## Build order

1. `report.css` + `report_html.py` render layer + its unit tests.
2. DesignSync bundle (preview HTMLs sharing `report.css`) → `create_project` → push.
3. Wire both tools + `--format html` CLI + tests.
4. ADR-0082 + README count refresh.
5. Cold `pr-reviewer` + `envmon-spec-checker` → PR (draft), closes #163.

## Invariants honored

- **arcpy-free / core-stdlib**: render layer core is pure stdlib; no core→adapter deps.
- **No new required dependency**; photo path reuses the existing `report` optional extra.
- **Canonical config** untouched; DRAFT markers not involved.
- **Additive**: Markdown default preserved; XLSX photo tool untouched.
