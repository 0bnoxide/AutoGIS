# Montana State Library HFDEM downloader design

Approved direction, 2026-11-10: archive first; require explicit project selection when discovery finds multiple downloadable projects. Preserve measured raster resolution separately from published accuracy/confidence claims and their evidence. Unknown is not an estimated confidence score.

## Scope and interfaces
Add `download-msl-dem` and `DownloadMSLDEM`; leave OpenTopography unchanged. Core discovery/acquisition is stdlib and arcpy-free. Optional `msl` extra supplies rasterio, pyproj and pyshp for headless processing and shapefile geometry. ArcGIS Pro uses an adapter backend. Both share archive selection, metadata compatibility checks and provenance.

AOIs are Polygon/MultiPolygon in WGS84 (GeoJSON or selected Pro features), not just bounding envelopes. Bboxes become polygons. REST queries use explicit inSR=4326, spatial intersects, field schemas and paginated object IDs. Project names identify source collections; preserve complete original inventory attributes/domain definitions and source URLs. All intersecting downloadable projects are shown; users explicitly pick one or more when multiple exist. Explicit multiple selections do not waive datum/grid checks. Request-only/non-HFDEM projects remain visible in plan warnings.

Quad archives are default. An explicit project-mosaic mode may use verified ProjectDownload/Mosaics/HFDEM.zip URLs, with same preflight. Validate official HTTPS source paths and file existence. Plans report exact size where advertised, unknown sizes, source coverage labels, cached status and disk space. Missing archives fail rather than imply coverage. Large or unknown network download size requires explicit allow-large-download; default threshold 1 GiB total. Dry-run never downloads archives or creates output/cache directories.

Stream into unique sibling partials, bounded retries, strict status/content length, CRC verification, SHA256 cache receipts and validators. No replacement of unrelated files. ZIP validation rejects traversal, Windows-special paths, duplicates/case collisions, symlinks/encryption, excessive expanded bytes or unsafe compression; extract only selected HFDEM rasters plus exact companion XML. Project folder matching is exact; unknown `Quads` roots fail with attribution guidance, not a guessed project.

Inspect artifact CRS/grid/NoData/type and artifact-specific vertical metadata (GeoTIFF/companion XML). Inventory Native* describes original delivery, not necessarily distributed tiles; preserve separately and never silently substitute. Unknown vertical metadata is allowed only for a single project's unchanged native surface, loudly recorded; no conversion or cross-project mosaic until verified. All native grids must match CRS, resolution and alignment; an explicit target CRS/resolution allows horizontal resampling. Vertical datum transformations are unsupported and never inferred. Unit conversion (m, international foot, US survey foot) changes values only, preserves NoData and datum, and requires known source units.

Clip real AOI; default native grid, pixel-center polygon mask and outward pixel-aligned extent. Count AOI and valid output cells, preserve gaps as NoData and warn when incomplete. Do not claim subpixel geometric coverage or source accuracy from those counts. Output GeoTIFF and .tif.json are staged before publication, checked for overwrite safety, with rollback on write failure. Provenance includes source URLs, archive SHA256/validators/timestamps, project/quad IDs, original and output metadata, actual AOI, all operations, coverage and QA. Accuracy records contain value/statistic/units/confidence only when explicitly present in source XML; raw text and source locations remain traceable. Quality level is a publisher category, not measured accuracy.

## Preliminary evidence (live 2026-11-10)
Inventory: https://mslgis.mt.gov/arcgishosting/rest/services/GEOINFO/LidarInventory/MapServer (quads 1, projects 2). 2814 downloadable quad records; directory does not contain all (e.g. 44111g6, 46107f8, 48106e3 returned 404). Schema includes NativeHorizontalUnits/NativeVerticalUnits.
44107h1.zip: 609485 bytes, BIGHORN_2019_BHcntyQL2/HFDEM/44107h1_HFDEM.tif, F32, EPSG6514, 0.9144 m pixels, NoData=0, no vertical TIFF tags or HFDEM XML. Inventory original units disagree with distributed horizontal raster. 44104h1.zip: two projects, mixed products, HFDEM-specific XML includes NAVD88 meters. 45111f4.zip: 1.893 GB, multiple projects plus ambiguous Quads/HFDEM root; never guess its attribution.
Actual ImageServer exists: https://mslgis.mt.gov/arcgishosting/rest/services/GEOINFO/LidarBareEarthDigitalElevationModel/ImageServer . Raw lock-raster TIFF export matched all 646 valid archive pixels in a 32x32 native-grid window, but returned elevations for all 378 archive NoData cells. Thus evaluated but not qualified as equivalent acquisition backend; no silent fallback. Official webmap 396a82e93c8042be9bc314bdfe9396b2 labels raw service values meters, but this does not establish all ZIP units.
Official metadata directory: https://ftpgeoinfo.msl.mt.gov/Data/Spatial/MSDI/Elevation/Lidar/MetadataLidarProjects.pdf . Published source is informational; it is not a guarantee of engineering/survey fitness.

## Validation
Mock REST/HTTP and hostile small archives; synthetic raster grids, holes, overlaps, unknown/mixed metadata; CLI/toolbox real seams; OpenTopography regression. Live small archive and native ArcPy raster QA, then interactive selected polygon/map acceptance when available. Full arcpy-free suite and independent final-head review. No publish/merge without owner approval.
